# Decision 
Using Relational Database

## Context

The system needs to store users, departments, requests, approvals, categories, and request history.

Most of this data is connected. For example, a user submits a request, a department handles it, and a request can have approvals and history.

## Decision

I decided to use a relational database.

## Why

1- A relational database fits this system well because the data has clear relationships.

2- It also makes it easier to keep the data organized and make sure the links between users, departments, requests, and approvals stay correct.

## Consequences

- Related data is easier to manage.
- SQL can be used to get the needed data.
- It is easier to keep the data consistent.
- The structure is less flexible than a non-relational database.
